# 换到北京或其他场地

服务不依赖杭州校园地图。到新场地新建地图即可，不修改代码，不把旧地图坐标改成新场地。

1. 复用当地已运行的 GNSS 原语，配置正确的 `gnss_provider_id`、ROS 域和实际步态反馈输入；不要重复打开串口。
2. 到室外等有效定位后，开始新地图采集。原点自动取录制中的首个有效 GNSS 点；无解、单点解或过期数据不决定原点。
3. 保存新 ID，例如 `beijing-field-v1`。原始经纬度仍保留；地图还保存该原点以及向东 X、向北 Y 的米制路网。
4. 补采时先加载这张地图，补采保持原点，不能把杭州地图加载后当作北京地图补采。
5. 导航执行接入时，定位程序必须读取当前地图的 `origin_wgs84`。不得保留杭州定位原点后直接使用北京参考路线。当前 Scene 已通过定位 Driver 自动接入；地图 ID、版本和原点不匹配时阻止导航。

原点是距离计算的参考点，与网页显示边界不同。Scene 的“显示全图”由路线横纵边界外扩决定，原点不必出现在画面中央，操作者也无需站在原点开始下一次补采。

已用杭州和北京两组经纬度验证：首次有效采集原点、保存重载、双向规划和补采保持原点。实际 GNSS、步态反馈和导航执行仍需在当地验收。
